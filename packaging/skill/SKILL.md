# UU 远控语音直输

将本机豆包语音识别通过已配对的加密通道写入远端 Mac 当前输入框。接收端支持可靠文字范围替换时实时显示，否则整句发送；不使用剪贴板粘贴。

## 开始

先确定本机/远端角色、是否已安装本工具、UU 是否能连接目标，以及目标应用。已有明确上下文时直接沿用。不要把设备示例当成固定目标。

- 两端程序位于 `assets/apps/`；完整源码在 `assets/source/`。
- 首次安装按 [配置与验证](references/setup.md) 操作。使用 `scripts/install-app.sh --role sender` 或 `--role receiver` 安装相应端；脚本只复制程序，不启动、不写配对码、不自动授予系统权限。
- 需要登录自启或自动恢复映射时，按 [后台运行与自动恢复](references/automation.md) 为使用者绑定自己的设备和规则；分享包不附带这些配置。
- 发现错误或实时显示异常时按 [故障定位](references/troubleshooting.md) 操作。
- 修改代码时先读 [实现约束](references/architecture.md)，构建入口为 `assets/source/scripts/build-app.sh`。

## 必须保持的行为

分享版未预设端口和配对码。为当前使用者选择空闲端口，首次生成新的随机配对码。UU 本地映射端口与发送端对应，远端目标端口与接收端对应；两端配对码相同。服务只监听远端回环地址，不额外开放公网监听或路由器端口。

不把使用者的密码、配对码、设备名称、地址、端口配置、日志或听写正文写回 Skill、源码或分享包。不要读取或展示钥匙串秘密来“诊断”；让用户在程序自己的配对界面输入。密码和系统验证窗口交由用户完成，安装 Skill 不代表已经授权新增系统控制权限。

更新已配置的应用前核对安装位置与标识，避免同名应用并行运行。更新可能使 macOS 再次要求钥匙串/辅助功能确认，不能凭旧授权状态假定新版正在工作。保留可恢复的旧程序，不覆盖用户已有配置。

远端输入验证使用专门的空白测试文档。编译、自检和网络握手通过只说明相应层正常；必须观察实际语音输入、结束后最终结果、连续两次触发，才能声称端到端正常。只有用户需要的目标应用经实际验证，才可声称它支持实时模式。
