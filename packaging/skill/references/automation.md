# 后台运行与映射自动恢复

1.0.0 包含登录自启支持和映射自动恢复，已修复映射正常时反复切回 UU 主页面的问题。配置按用户意愿启用，不预置设备、端口或规则。

## 登录启动

接收端首次启动会注册当前用户的登录启动项，使用 `open -a` 打开当前应用路径。菜单“开机自启”可开关；移动应用后重新启动一次以更新路径。发送端在 macOS 的“登录项”中添加实际安装的“远控听写.app”。安装脚本只安装程序，不自动启动应用或代办系统授权。

两台 Mac 需要已登录系统。UU 和本机豆包需可用；接收端不需要豆包。允许用户保持接收端后台常驻，只监听回环地址；断开桌面后本工具不强制关闭监听或 UU 映射。无需额外云服务，不新增公网监听。

## 为当前使用者绑定自动映射

先完成普通配对、UU 映射和语音输入测试。仅在用户希望自动恢复时执行：

1. 用 UU 自带的 `/Applications/UURemote.app/Contents/Helpers/uuyc-cli device list --json` 查找目标设备，结合用户指定的设备确认唯一 ID；再用 `device status --json` 验证这是活动的桌面控制连接。不要从本文或旧任务复制设备信息。
2. 用当前环境允许的电脑操作工具打开该设备的“端口映射”，确认目标地址是远端回环地址、两端端口与配对配置对应。读取该既有规则开关的可访问性 Identifier。规则按钮也可能同 ID，应确认读取的是有 0/1 值的开关；不能把规则名称当 ID，也不能猜一个数字。
3. 退出发送端后，写入**分享版发送端**偏好。下面全是占位符，必须替换为使用者自己的值，按工具的安全参数传递方式执行，不把替换结果保存回 Skill：

```sh
defaults write org.remotedictation.bridge uuAutoMappingTargetID -string '<当前目标设备 ID>'
defaults write org.remotedictation.bridge uuAutoMappingTargetName -string '<UU 中该设备的名称>'
defaults write org.remotedictation.bridge uuAutoMappingRuleID -string '<该映射规则开关的 Identifier>'
defaults write org.remotedictation.bridge uuAutoMappingEnabled -bool true
```

4. 重新启动发送端。菜单中出现“连接 UU 时自动恢复语音映射”，可以随时关闭。设备、规则或名称改变时重新确认绑定；不要复制发布者的偏好或启动项。

没有所需 CLI 或无法可靠读取规则时，保留手动映射即可正常听写，明确自动恢复尚未配置。只读 CLI 不提供映射开关 API；产品内部的界面适配不能视为对智能体使用任何 UI 自动化途径的授权。

## 行为与验收

- 只针对绑定设备的活动桌面控制会话。UU 不在前台或正在听写时不操作窗口。
- 先检查 UU 进程拥有的配置端口。正常就完全不动窗口；连续两次明确缺失才尝试恢复。查询异常时等待，不将异常当成断线。
- 接入后可能需要数秒完成恢复；恢复后返回原窗口，用户主动切换窗口时让开。界面不匹配则报告错误，不猜按钮位置。
- 在允许中断测试连接的前提下，测试关闭映射后的恢复、断开再连接；切到远控停留至少 30 秒确认没有反复跳转，再连续听写两句。验证监听正常不能替代语音验证。
- 此适配已在中文界面的 UU 4.45.0 验证。其他版本或语言先检查实际界面，不保证所有版本通用。
