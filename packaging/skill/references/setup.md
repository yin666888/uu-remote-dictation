# 配置与验证

## 环境

两台 macOS 13 或以上的 Mac，程序包含 Apple Silicon 与 Intel 架构。本机安装并可正常使用豆包语音输入法，语音快捷键在豆包中设置；两台电脑可通过 UU 远程连接。构建源码另需 Swift/Command Line Tools，运行预编译程序不需要。

这是第三方个人工具，不附带豆包或 UU 软件、账号或授权。程序采用本地临时签名，没有开发者公证。首次打开可能被 macOS 拦截；让用户自行判断来源并在系统“隐私与安全性”界面批准本次打开，不关闭 Gatekeeper 或全局降低安全设置。

## 两端安装

- 本机（说话的电脑）：`assets/apps/远控听写.app`。
- 远端（被控电脑）：`assets/apps/远控直输接收端.app`。

可用 `scripts/install-app.sh --role sender|receiver --destination <应用目录>`；默认使用当前用户的 `~/Applications`。脚本遇到同名且标识不同的程序会停止，不能用分享版无提示覆盖已有私人配置版本。更新同标识程序前先退出它，脚本把旧副本移入当前用户废纸篓。

若工具有足够能力，使用现有文件传输功能将接收端传到远端，并在远端安装；仅有本机文件访问能力时明确哪些远端步骤仍需用户完成。

## 配对和映射

1. 在接收端菜单栏打开“配置直输配对…”。选择一个空闲的高位 TCP 端口（通常从 49152–65535 选取），在当前机器上检查是否被占用后填写。分享版没有预设端口。
2. 点“生成配对码…”，由用户将新生成的 64 位十六进制码传到本机的配对窗口。两端使用同一码，分别保存；该码仅保存在各自系统钥匙串中。
3. 在 UU 为本次连接建立 TCP 端口映射：本机回环地址上的空闲端口 → 远端 `127.0.0.1:<接收端口>`。本机映射端口可以与接收端口不同，发送端填写本机映射端口。保持映射连接工作；某些 UU 版本关闭映射窗口会断开转发。
4. 本机按系统提示启用发送端的辅助功能/输入监控；远端启用接收端的辅助功能。向用户解释这些权限分别用于识别快捷键、向应用输入文字，依环境权限规则处理确认，不代办密码验证。
5. 两端出现钥匙串验证时，用户分别在对应电脑完成验证。不要让用户把登录密码发给聊天。

同局域网和异地均可沿用 UU 连接及端口映射，不需要共享家庭网络地址或额外开放公网端口。实际可用性依赖双方 UU 连接和版本功能。

## 使用与验收

1. 在远端“文本编辑”新建空白测试文档，点入输入区。
2. 本机轻点豆包“免按模式”设置的快捷键开始，等豆包启动后说话，再轻点一次结束；或按住豆包“长按模式”设置的快捷键说话、松开发送。两项设置可以不同。改键后在空闲时约 1 秒自动同步，无需在本工具再设置。
3. 本工具正常状态没有浮层，豆包自己的提示仍由豆包显示。支持实时更新的输入框会边说边出现文字，最终识别纠正同步替换。
4. 重复两次，确认无重复追加、最终文字保留、下一轮可触发。再验证用户实际使用的输入框。
5. Esc 取消。轻点模式下其他按键/鼠标操作也会取消；50 秒后自动结束。取消时只在原目标、内容和光标都未改变时恢复原来的文字，外部修改后可能保留部分草稿，需检查。

普通用户可以只安装程序。使用 Codex 的用户把整个 Skill 文件夹放入 `~/.codex/skills/uu-remote-dictation/` 后，在新会话调用 `$uu-remote-dictation`。这里的路径只使用当前用户的家目录，不包含发布者的账号。

## 快捷键兼容性

已在真实双 Mac 环境验证左 Ctrl 和 Fn 的长按、轻点、实时输入与连续触发。普通键和修饰键组合有自检覆盖，仍需在使用者环境实测；Caps Lock 暂不支持。清空豆包某一模式的快捷键会禁用对应模式，不回退到固定 Ctrl。读取失败会明确提示，豆包升级改变设置存储格式后可能需要更新本工具。


## 后台运行与自动恢复（可选）

需要减少每次手动启动时，使用 [后台运行与自动恢复](automation.md)。接收端可保持只监听本机回环地址；双方登录后启动程序，发送端按使用者自己的 UU 目标及映射规则恢复连接。分享版自动映射默认关闭，没有任何发布者的设备绑定。先完成基本配对和两轮语音测试，再配置和验证自动恢复。
