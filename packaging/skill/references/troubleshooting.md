# 故障定位

按当前现象缩小范围，不要每次重装或重配所有设置。

- 无触发：发送端是否运行、本机辅助功能/输入监控、UU 是否为当前目标窗口；用 `--check-shortcuts` 确认读到的长按/免按键与豆包设置相同。左右修饰键按配置区分，不固定为左 Ctrl。输入焦点在本机普通应用时快捷键会透传。
- Fn 长按可用但轻点立即取消：检查是否为 3.2.0 或以上。已知 Fn 松开后可附带硬件键码 179；旧版将它误判为其他键。新版本仅过滤紧随已捕获 Fn 松开的这一事件对，不通过放宽长按阈值修复。
- 两端连接失败：接收端是否运行和监听所配回环端口、UU 映射是否在线、两端端口对应、配对码是否由用户确认一致。不要打印密钥。更新后进程可能在钥匙串验证中等待。
- 手势正常但无文字：检查豆包本机独立听写；确认接收端辅助功能开关和远端普通输入框焦点。密码输入框不接受输入。
- 只有最终文字：日志中的 `Receiver preview capability=false` 表示目标缺少可靠的文字/选区读写能力，已自动回退。若为 true，观察 `IME draft ... marked=true finalizing=false` 和 `Preview acknowledged sequence=...` 是否在结束前出现。
- 有实时文字但中途停止：检查焦点、光标、原文是否被手动或应用自动修改；为避免覆盖内容，程序会停止。先检查已显示内容再重新听写，不能盲目补发。
- UU 主页面与远控画面反复跳转：先关闭发送端菜单的“连接 UU 时自动恢复语音映射”，保留已建立的映射和语音输入。确认使用 1.0.0；端口正常时必须直接跳过全部窗口操作，不能凭映射窗口不可见反复恢复。用 `--check-mapping-listener` 检查 UU 所有的本机监听端口，只输出 READY/ABSENT/UNKNOWN，不读取配对码。
- 登录后接收端没运行：核对应用是否移动、系统是否允许其后台项目、接收端“开机自启”是否开启；自启发生在登录后，不会解锁系统。用户手动退出后不会立即强制重启。
- Qoder CN 不实时显示：此版本对它固定使用最终整句字符输入，避免第一轮后切回不可靠的 AX 写入。先验证连续两轮最终文字，不把不实时误判为故障；其他 Electron 应用仍按可靠能力协商。
- 第二轮不触发：程序会审计 UU 与豆包的 HID 监听顺序并在空闲时重排；检查是否有多个发送端实例或新版本权限未生效。

程序提供 `--self-test`（内存目标和本机加密回环，不实际向应用输入）、`--diagnostics`、`--check-connection`、`--check-shortcuts`（只读快捷键，不读取配对密钥）。诊断输出可能含本机状态，分享给其他人前需自行检查；不要收集无关系统日志。分享版日志子系统为 `org.remotedictation.bridge`，只需读取相关短时间范围，不记录听写正文。

CLI 构建或只读诊断与 UI 操作是不同能力。若需要操作原生应用、UU、系统设置或远端屏幕，使用环境允许的电脑操作工具；不能因 UI 工具失败而改用其他未获允许的 UI 自动化途径。远端安全验证需用户本人完成。
